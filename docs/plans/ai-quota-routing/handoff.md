## 必須保留的已確認決策

1. 任務歸屬使用平台無關的 Git Repository 來源資訊判定為 task profile，不綁定 GitHub 或任何特定 Git 供應商。
2. 每個 AI 額度來源分別定義額度歸屬與可支援的 task profile；任務只能使用明確宣告支援它的來源。
3. 個人額度來源可以支援個人與公司任務；公司額度來源可以支援公司任務，但不得支援個人任務。
4. 無法確認任務歸屬時，不得自行選用未明確支援的額度來源；remote 的解析、匹配與衝突處理尚未決定。
5. 真實 Git 來源、帳號、額度歸屬、可支援 task profile 與額度資訊只能存在本機私有設定；tracked file 只保存通用規則與去識別化範例。
6. 每項額度的重置時間可能不同；未來決策需要理解各自的可用週期，但目前尚未決定如何分配或使用 AI。
7. 額度來源的支援權限先於 AI 能力與額度最佳化；後兩者不能成為使用未授權來源的理由。
8. 每個 AI 都必須具備設定預留額度的能力；同一 AI 的不同帳號或額度來源也必須各自獨立。
9. 使用者必須能依需求持續調整各項預留額度，不能只在初次設定時決定後永久固定；個人 Copilot Review 是目前已知的保障用途之一。
10. 預留額度如何影響 AI 選擇尚未決定；其表示方式、調整介面、約束強度與生效方式也尚未決定。

## 接手時不要做的事

- 不要開始修改 production code、script、hook、skill 或 installer。
- 不要建立供應商清單或假設一定使用某個 AI CLI。
- 不要把平均分配、固定比例、輪替或任何其他 AI 使用策略寫成已確認需求。
- 不要把額度歸屬與可支援的 task profile 合併成同一個對稱規則。
- 不要將 GitHub organization 規則當成唯一方案。
- 不要提前決定 Git remote 的正規化格式、匹配優先序或 authoritative remote。
- 不要提前決定預留額度的數值、比例或設定格式。
- 不要將預留額度設計成初次設定後不可調整的固定值。
- 不要要求使用者把真實公司網域、repository 或帳號資訊寫入 Git。
- 不要把尚未確認的提議寫成既定需求。
