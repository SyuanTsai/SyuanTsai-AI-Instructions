## 必須保留的已確認決策

1. 任務歸屬使用平台無關的 Git Repository 來源資訊判定為 task profile，不綁定 GitHub 或任何特定 Git 供應商。
2. 每個 AI 額度來源分別定義額度歸屬與可支援的 task profile；任務只能使用明確宣告支援它的來源。
3. 個人額度來源可以支援個人與公司任務；公司額度來源可以支援公司任務，但不得支援個人任務。
4. 無法確認任務歸屬時，不得自行選用未明確支援的額度來源；remote 的解析、匹配與衝突處理尚未決定。
5. 真實 Git 來源、帳號、額度歸屬、可支援 task profile 與額度資訊只能存在本機私有設定；tracked file 只保存通用規則與去識別化範例。
6. 每項額度的重置時間可能不同；偏好的 AI 資源不可用時，較接近重置且可能浪費的可用額度具有較高使用優先性。
7. 額度來源的支援權限先於 AI 能力與額度最佳化；後兩者不能成為使用未授權來源的理由。
8. 每個 AI 都必須具備設定預留額度的能力；同一 AI 的不同帳號或額度來源也必須各自獨立。
9. 使用者必須能依需求持續調整各項預留額度，不能只在初次設定時決定後永久固定；個人 Copilot Review 是目前已知的保障用途之一。
10. 自主路由不得侵入預留額度；其表示方式、調整介面與具體生效方式尚未決定。
11. 不在 Git Repository 中、沒有 remote 或無法判定 task profile 時，首次必須詢問使用者，並將確認結果保存在本機私有設定，供後續相同任務來源重用。
12. 任務來源改變或來源資訊與本機紀錄衝突時，必須重新詢問，不得靜默沿用或覆寫分類；相同任務來源的識別方式與儲存格式尚未決定。
13. 多 Repository 情境以當前任務為 task profile 判定單位；輔助 Repository 不各自路由，若來源使當前任務歸屬互相衝突或無法判定，必須詢問使用者。
14. 合格來源中優先採用使用者設定的 AI 與模型偏好，但不得突破 task profile 支援權限或侵入預留額度；偏好資源不可用時，再依額度重置急迫性、成功率與切換成本選擇替代來源。
15. Codex App 作為主控，負責理解及拆分任務、派工、協調執行與整合結果；除了 Codex 本身可用的 AI 資源外，其他 AI 資源只有使用者加入後才納入可派工範圍。
16. Codex 本身可使用的額度也是可派工 AI 資源，並適用相同的 task profile 授權、額度與預留規則；其他 AI 資源仍須由使用者加入。
17. AI 資源以實際共享的帳號或額度來源為整體，可提供多個 AI、模型或執行模式選項；共用額度的選項共同套用預留量。同一 AI／模型因帳號或額度來源不同，可以存在於多個獨立資源中。
18. Codex 在理解及拆分任務時，自主判斷各子任務的必要能力與適合的 AI、模型及執行模式；使用者不需逐次判斷或維護完整能力對照表。
19. 能力資格只使用環境已知或 AI 資源提供的客觀資訊進行低成本不相容篩選，不得臆測模型、工具或權限，也不為每次派工額外呼叫 AI、探測或執行基準測試；資訊不足且影響安全或完成時才詢問使用者。
20. Codex 在每次派工時依任務、授權、必要能力、額度、預留與偏好規則選擇實際使用的 AI 資源及其模型或執行模式。
21. task profile 仍以當前任務為單位並由拆出的子任務繼承；Worker 若未來需要存在，只視為內部實作概念，不是目前需求討論重點。

## 接手時不要做的事

- 不要開始修改 production code、script、hook、skill 或 installer。
- 不要建立供應商清單或假設一定使用某個 AI CLI。
- 不要把平均分配、固定比例或輪替寫成已確認的預設 AI 使用策略。
- 不要把 AI 與模型偏好解讀成可以突破 task profile 支援權限或預留額度的人工覆寫。
- 不要把同一共享額度來源下的模型或執行模式視為各自擁有獨立額度及預留量。
- 不要為能力資格判斷額外呼叫 AI、執行探測任務或建立複雜評分。
- 不要要求使用者逐次判斷模型能力或維護完整能力對照表。
- 不要把額度歸屬與可支援的 task profile 合併成同一個對稱規則。
- 不要因同一任務出現多個 Repository，就預設拆分任務或分別進行 AI 路由。
- 不要將 GitHub organization 規則當成唯一方案。
- 不要提前決定 Git remote 的正規化格式、匹配優先序或 authoritative remote。
- 不要提前決定預留額度的數值、比例或設定格式。
- 不要提前決定本機任務來源紀錄的識別鍵、儲存格式或管理介面。
- 不要展開 Worker、Adapter、資料結構、通訊協定或其他內部實作細節。
- 不要將預留額度設計成初次設定後不可調整的固定值。
- 不要要求使用者把真實公司網域、repository 或帳號資訊寫入 Git。
- 不要把尚未確認的提議寫成既定需求。
