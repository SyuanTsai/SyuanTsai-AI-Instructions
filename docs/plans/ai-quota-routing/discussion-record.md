# AI 額度自主路由：討論與決策紀錄

## 文件定位

- 狀態：目標探索中，尚未進入實作規劃。
- 工作分支：`codex/plan-ai-quota-routing`。
- 用途：保存已確認的目標、限制、理由與未決問題，作為後續討論的主要依據。
- 更新原則：只有經使用者確認的內容才能列為「已確認決策」；尚未確認的內容應保留在「待討論問題」。

## 1. 問題背景

在分析問題或進行功能修改時，使用者不希望每次都手動選擇要由哪一個 AI 執行，也不希望所有工作固定消耗同一個 AI 或帳號的額度。

這個需求的核心是讓 Agent 在合法的額度範圍內自主決定使用哪個 AI，同時保留其他必要工作所需的額度。具體如何分配或使用 AI 尚未討論。

## 2. 目前目標

當使用者提出問題分析或功能修改任務時，Agent 應先判定 task profile，再從明確允許支援該 profile 的 AI 額度來源中自主決定使用哪個 AI。每個額度來源同時保有自己的歸屬、可支援任務範圍與可調整的預留額度。

正常情況下，使用者不需要逐次指定 AI、模型、帳號或額度來源；沒有明確宣告支援目前 task profile 的額度來源不得使用。

## 3. 已確認決策

### 3.1 額度歸屬與可支援任務分開定義

- 每個 AI 額度來源需要分別表達「額度屬於哪個 profile」及「允許支援哪些 task profile」，兩者不是同一個概念。
- 任務能否使用某個額度來源，取決於該來源是否明確宣告支援目前 task profile，而不是要求任務與額度具有相同歸屬。
- 個人額度來源可以支援個人與公司任務；公司額度來源可以支援公司任務，但不得支援個人任務。
- 同一 AI 的個人帳號與公司帳號是不同額度來源，各自具有獨立的歸屬、可支援任務範圍與預留額度。

### 3.2 各項額度具有不同重置條件

- 不同 AI 或帳號的額度重置時間不盡相同，每項額度必須獨立看待。
- 這項事實表示未來的 AI 使用決策需要理解不同額度的可用週期，但目前尚未決定如何分配或選擇 AI。
- 平均分配、固定比例、round-robin 或其他使用策略都不屬於目前已確認決策。

### 3.3 以 Git Repository 來源判定任務歸屬

- 任務歸屬以 Git Repository 的來源資訊判定，不綁定 GitHub 或其他特定 Git 平台。
- 判定結果應對應 task profile，讓不同組織或客戶可在未來加入，而不需更換整體判定概念。
- 無法確認任務歸屬時，不得自行選用未明確支援的額度來源；具體 remote 解析、匹配順序與衝突處理留待行為設計階段決定。

### 3.4 真實識別資訊不得進入 Git

- 真實 Git 來源、帳號、額度歸屬、可支援 task profile 與額度資訊只能保存在本機私有設定中。
- 受版本控制的內容只能保存通用規則與去識別化範例，不得要求公開真實公司或個人識別資訊才能完成分類。
- 功能不得要求將真實公司或個人識別資訊寫入 tracked file，才能完成分類。

### 3.5 每個 AI 的額度來源都能獨立設定預留額度

- 每個 AI 都必須具備設定預留額度的能力；同一 AI 的不同帳號或額度來源也必須各自獨立。
- 使用者必須能依需求持續調整各項預留額度，不能只在初次設定時決定後永久固定。
- 這項能力不代表每個 AI 必須設定相同的預留量，也不代表目前已決定預留量的值。
- 預留額度用於保障不一定由自主路由發起、但會消耗相同額度的必要工作，例如個人 Copilot Review。
- 目標是避免自主決策耗盡這些必要工作需要的額度；預留額度如何影響 AI 選擇尚未決定。
- 預留量的表示方式、大小、調整時機、約束強度與人工覆寫規則留待後續討論。

## 4. 目前概念流程

```text
Git Repository 來源資訊
→ task profile
→ 篩選明確支援該 task profile 的 AI 額度來源
→ 每個 AI 的各額度來源分別套用使用者目前設定的預留額度
→ 自主決定使用哪個 AI（決策方式待討論）
```

這個順序只描述目前目標與硬性邊界，不代表已決定 AI 的分配、評分或選擇方式。

## 5. 目前階段的非目標

- 尚不決定 CLI、背景服務、hook、skill、設定檔或其他實作形式。
- 尚不決定支援哪些 AI 供應商、模型或帳號。
- 尚不決定額度歸屬與可支援 task profile 的實際設定格式。
- 尚不定義如何取得、快取或更新剩餘額度與重置時間。
- 尚不決定預留額度使用固定值、比例、任務數量或其他表示方式。
- 尚不決定使用者透過何種介面調整預留額度，以及調整如何生效。
- 尚不決定平均分配、固定比例、輪替、優先級或其他 AI 使用策略。
- 尚不設計具體的 AI 選擇演算法、權重或評分公式。
- 尚不開始撰寫 production code、安裝腳本或測試。

## 6. 待討論問題

1. 不在 Git Repository 中、沒有 remote 或判定為 `unknown` 的任務，是否一律先詢問使用者？
2. 同一任務同時涉及不同 task profile 的多個 Repository 時，應拆分任務、採最嚴格邊界，還是必須詢問使用者？
3. 在合法範圍內應依哪些目標決定使用哪個 AI？
4. 當首選 AI 無法執行或額度不足時，允許 Agent 在其他合格來源間自動切換到什麼程度？
5. 使用者是否需要看到每次選擇所依據的 task profile、額度來源、預留額度與簡短理由？
