# Third-party raw Skill source contract v1

This is the central normative opt-in path for an unmodified external Skill whose owner does not provide this Standard's `catalog/source.json` or `agents/openai.yaml`. It does not convert a Plugin into a Skill or modify the external package. Adoption requires the normal authority review and merge before an approved descriptor may enable a production Catalog pin.

The [synthetic descriptor example](examples/third-party-raw-skill-source-v1.json) illustrates the strict metadata shape. Its hashes and repository are placeholders and are not adoption evidence.

## Ownership and scope

- Dedicated owned sources continue to satisfy Standard §§4.4, 4.6 and 5.1. The v1 alternate path applies only when both source-owned artifacts are explicitly absent. An artifact that appears later changes the contract and requires a new reviewed candidate; it must not be silently ignored.
- Central owns a descriptor validated by [`third-party-raw-skill-source-v1.schema.json`](schemas/third-party-raw-skill-source-v1.schema.json). Its `skills` is the complete adopted package inventory. `hostInterface` is central routing/display information with the reviewed interface value constraints, including an explicit `$skill-id` prompt reference. It is not upstream metadata and is not installed into the raw package.
- The adapter validates portable `SKILL.md` and every byte of each declared `skills/<id>/**` package. Exact stable IDs, source paths and `.agents/skills/<id>` targets must agree. Additional bytes anywhere inside an adopted package change its content hash. Other repository surfaces are excluded from projection.
- Each descriptor binds an exact GitHub repository, full immutable commit, actual acquired archive SHA-256, per-Skill content hashes, and every applicable original license document with its source path and SHA-256. Inventory hashing uses the existing ordinal repository-relative `path + TAB + sha256 + LF` algorithm.
- Descriptors must reject unknown fields, duplicate or case-conflicting keys, unsafe paths, duplicate identities, symlinks/reparse-backed content, missing documents and identity/hash mismatch. The adapter must independently expand the actual archive through the existing central safe ZIP/acquisition module and match its complete adopted packages and legal documents to the supplied source tree and descriptor. Validation must recheck the bound bytes before returning. The descriptor and adapter must be frozen as authority inputs for a formal run.

## Candidate, approval and licensing

`reviewState=candidate` and `licenseReview=pending` permit inert package-integrity review and source-only checks. Source-only checks **MUST NOT** require adoption approval before collecting source evidence. A valid candidate/pending descriptor **MUST** be eligible for the canonical `-SourceValidation` route, retaining `adoptionApproved=false` and `releaseEligible=false`. Source checks do not authorize adoption, accept licenses, change descriptor review state, or replace Human Approval. `approved` requires nonempty actual central human-review evidence and accepted license-review evidence. An unsubstantiated approved claim **MUST** fail in both source-check and adoption routes. The validator cannot authenticate a URL's review decision; the canonical review/lifecycle controls must verify that evidence against the same candidate. A self-authored descriptor or successful package check cannot replace those controls.

[`Validate-ThirdPartySkillSource.ps1`](../../scripts/Validate-ThirdPartySkillSource.ps1) is a package adapter. `-RequireApproved` must be selected for formal adoption. Its report always declares `validationKind=third-party-package-only` and `releaseEligible=false`; `adoptionApproved` describes only the descriptor state. Even an approved descriptor is not authorization to release or install.

License delivery retains original bytes and provenance through the existing license delivery module. `documents-present` is not legal acceptance. Third-party references, embedded assets, copyright notice obligations and trademarks require review. Unresolved necessary licensing blocks approval; a usage restriction must not disguise redistribution without the necessary rights. Additional centrally owned legal evidence stays separately attributable and must not masquerade as an upstream file.

## Unchanged validation and deployment gates

The raw path replaces only source ownership of inventory/interface metadata. It **MUST NOT** replace safe YAML parsing, the provider's portable package contract, actual `skill-validator`, `skill-tools`, complete SkillSpector Static (no-LLM), repository general/Pester checks, frozen tool receipts, severity/coverage rules, Human Approval, or post-install verification. A package-only or ordinary Core-only PASS **MUST NOT** substitute for `-SourceValidation`.

Use the existing Core v2 `sourceValidation.packageAdapter` dispatch with this CLI's explicit `-SourceValidationEnvelope` mode. It takes the supervised candidate root, checks the exact active inventory and emits only a package-stage envelope with the retained raw report. Source dispatch does not implicitly select `-RequireApproved`; an explicit adoption caller selecting that switch **MUST** still reject a pending descriptor. Freeze the CLI, imported module closure, schema, descriptor and original archive with the run's other authority files; validation must not reacquire them. The canonical envelope must bind its output and all native tool reports to one candidate, authority and fresh RunId. The complete adopted package set must equal the runner's discovered active inventory. For a raw source with additional unadopted packages, prepare a controlled exact archive projection of the adopted package set and original legal documents, retaining original repository paths and provenance; bind that projection and its exact source archive in acquisition evidence. Never trim resources within an adopted Skill or execute unrelated upstream root maintenance scripts.

Source checks are supplied by the central adapter and its versioned tests for the raw ownership contract, not by inventing an upstream test suite. Existing source-stage ordering and typed general/Pester evidence remain mandatory. The same candidate must pass formal function acceptance and isolated managed installation before deployment reception. Host dependency absence must identify affected capabilities; it must not silently trigger downloads or mark an unexecuted capability passed.

Production activation uses a separately reviewed Catalog/source-pin/Lock change. A non-default profile or explicit `includeSkills` selects the package. Changes to the upstream pin, declared package set, license documents or ownership metadata require a new descriptor, applicable malicious-content review and the normal source gates. Updates remain notify-only until approved. Recovery uses the previous verified pin and hash-aware managed reconciliation, preserving customized/unmanaged files and personal profiles.

## Authority regression

The authority gate must run the raw adapter's positive and negative regression suite through `skill-repository-standard.Tests.ps1`. Workflow and resolver-hardening regressions must retain the same authority entry point and source-tool/severity policies. No third-party path creates an alternate release or security gate.
